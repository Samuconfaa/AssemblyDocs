Hello World e le chiamate di sistema

Il primo programma completo. Per scrivere sullo schermo l'assembly non ha un'istruzione «stampa»: bisogna chiedere aiuto al sistema operativo.

Teoria

Il programma completo

.model small
.stack 100h

.data
    msg db "Hello, World!", 0Dh, 0Ah, "$"

.code
main proc
    mov ax, @data        ; imposta il segmento dati
    mov ds, ax

    mov dx, offset msg   ; DX = indirizzo del testo
    mov ah, 09h          ; servizio 09h: stampa stringa
    int 21h              ; chiama il DOS

    mov ah, 4Ch          ; servizio 4Ch: termina il programma
    mov al, 0            ; codice di uscita 0 = nessun errore
    int 21h
main endp
end main

Eseguilo passo per passo

Premi «Avanti» per eseguire il programma un'istruzione alla volta e guardare registri e schermo.

Che cos'è una chiamata di sistema

Il programma non può parlare direttamente con lo schermo, il disco o la tastiera: l'hardware lo gestisce il sistema operativo, che conosce tutti i dettagli dei vari dispositivi. Quando il programma ha bisogno di un'operazione di questo tipo, la chiede al sistema operativo: questa richiesta è una chiamata di sistema (system call).

Nei sistemi moderni questa separazione è imposta dalla CPU stessa: i programmi non possono toccare direttamente l'hardware, ma solo passare dalle chiamate di sistema, che sono l'unica «porta» controllata. Il DOS era meno protetto, ma usa lo stesso schema.

Come funziona int 21h

Sull'8086 le chiamate di sistema usano le interruzioni software: l'istruzione int n (dall'inglese interrupt) fa saltare la CPU al codice del sistema operativo associato al numero n. Per il DOS il numero è 21h. Passo per passo:

  1. Prima della chiamata, il programma prepara i registri: in AH il numero del servizio richiesto, negli altri registri (DX, AL...) i parametri.
  2. int 21h (due byte: CD 21) viene eseguita: la CPU salva sullo stack FLAGS, CS e IP, per sapere dove tornare.
  3. La CPU cerca dove si trova il codice del DOS nella tabella dei vettori di interrupt, che si trova all'indirizzo fisico 0000:0000. Ogni voce occupa 4 byte (offset e segmento della routine), quindi la voce dell'interrupt 21h è all'indirizzo 21h × 4 = 84h, cioè 0000:0084h.
  4. La CPU salta a quell'indirizzo ed esegue il codice del DOS.
  5. Il DOS guarda AH per capire cosa fare, esegue il servizio (per esempio scrive sullo schermo) e termina con l'istruzione iret.
  6. iret ripristina IP, CS e FLAGS dallo stack: il programma riprende dall'istruzione dopo int 21h.

Per stampare un singolo carattere:

mov dl, 'A'      ; il carattere da stampare
mov ah, 02h      ; servizio: stampa un carattere
int 21h
Curiosità: Linux

L'idea è la stessa su Linux a 32 bit: il numero del servizio va in EAX e i parametri negli altri registri. Per stampare si usa il servizio «write» (numero 4):

mov eax, 4        ; numero del servizio: write
mov ebx, 1        ; 1 = schermo (stdout)
mov ecx, msg      ; indirizzo del testo
mov edx, len      ; quanti caratteri stampare
int 80h           ; chiama il kernel

Nei sistemi a 64 bit si usa l'istruzione syscall, ma il principio è identico: numero del servizio in un registro, parametri negli altri, un'istruzione speciale per passare la parola al sistema operativo.

Come provarlo

Copia il programma in un editor, salvalo come hello.asm e:

  • con emu8086 incollalo nell'editor e premi «Emulate» poi «Run» (puoi anche eseguirlo passo per passo e osservare i registri);
  • con DOSBox: assembla con tasm hello.asm, collega con tlink hello.obj ed esegui hello.exe (oppure gli equivalenti MASM: ml, link).

È esattamente il percorso del capitolo 3: sorgente → assembler → linker → eseguibile.

In breve
  • Per usare lo schermo si chiede un servizio al sistema operativo: chiamata di sistema.
  • Sull'8086/DOS: numero del servizio in AH, parametri in altri registri, poi int 21h.
  • int salva FLAGS, CS, IP, salta al DOS tramite la tabella dei vettori (voce 21h all'indirizzo 0000:0084h); iret ripristina e ritorna.
  • 09h stampa una stringa che finisce con $, 02h un carattere, 4Ch termina il programma.
